Static analysis · C++23

Follow attacker input until it hits something dangerous.

Sentinel is a taint-analysis engine for JavaScript, Python and Go. It parses real syntax trees with Tree-sitter, tracks request data across variables and function calls to a fixpoint, and reports the exact path from source to sink.

The pipeline

A push becomes a triaged scan, with no step polling another.

GitHub signs a webhook, the gateway verifies it and queues the changed files, a worker analyses them, and each finding is checked against previously dismissed ones before it is stored and shown.

Go · Fiber

Gateway

Verifies the HMAC signature, records the scan, fetches changed files at the pushed commit and queues the job.

RabbitMQ

Queue

Durable queues with manual acks and publisher confirms, so a crash redelivers work instead of losing it.

C++23

Worker

Parses each file, runs the taint analysis and attaches the full source-to-sink trace to every finding.

FastAPI · pgvector

Triage

Embeds the finding and searches dismissed findings by cosine similarity. Close matches are suppressed.

Next.js · Postgres

Dashboard

Lists scans and shows each finding with its trace, severity, remediation and triage verdict.

Built to fail safely: unsigned webhooks are refused · redelivered webhooks do not scan twice · triage outages escalate rather than hide findings · stuck scans expire
The engine

Syntax trees, not regular expressions.

Matching on AST node types means a comment, a docstring or a string literal that merely looks like a vulnerability cannot produce a finding.

Parse

Each file becomes a concrete syntax tree using the Tree-sitter grammar for its language.

Extract

Assignments and calls are read by node type and field name, straight from the tree.

Summarise functions

For every function: which parameters reach a sink, and which flow back out. Solved to a fixpoint over the call graph, so a sink several helpers away is still found.

Propagate taint

Attacker-controlled sources spread through assignments to a fixpoint, so flows are found regardless of statement order.

Respect sanitizers

A sanitizer only clears the classes it actually protects against. HTML-escaping a value does not make it safe to splice into SQL, and the trace says so.

Report the path

Every finding carries its CWE, severity, confidence, a remediation and each hop from source to sink. SARIF output is built in.

Status

What works, and what is still a prototype.

Every part of the pipeline runs end to end. Two parts are deliberately simple, and the analysis has known limits.

Tested
  • Analyzer: 621 assertions in 32 suites across all three languages, with no broker or database needed.
  • Gateway: handler tests against the real routes, plus a store test against real Postgres.
  • End to end: a signed webhook through the real gateway, broker, worker and triage layer, checked 21 ways.
Known limits
  • Analysis is per file. A source in one module reaching a sink in another is missed.
  • No field sensitivity: tainting user.name taints all of user.
  • Triage embeddings use feature hashing, not a learned code model, and the store starts from 8 seeded examples.
Run it

Scan something in two commands.

The scanner needs only GCC 13 and three development packages. The full pipeline adds Docker, Go, Python and Node; the README walks through it.

# build the engine and run its test suite
cd worker && make && make test

# scan a directory, failing the build on anything high or critical
./build/sentinel-worker --scan ../demo/vulnerable-app --no-triage --fail-on high

# print the ruleset
./build/sentinel-worker --rules
